# 작업 프롬프트 — YouTube 영상 한 편을 어학 학습 카드 앱으로 만들기

> 이 문서는 **다른 에이전트에게 그대로 건네는 작업 지시서**입니다.
> 실제로 이 절차로 만든 결과물 두 개가 같은 상위 폴더에 있으니 참고하세요.
> - `korean-cards/` — 한국어 예능(자동생성 자막) → 일본어 학습자용, 383장
> - `japanese-cards/` — 일본어 인터뷰(공식 자막, `Name:` 화자) → 한국어 학습자용, 105장
> - `yubisaki-cards/` — 일본어 애니 1화(방송용 CC 자막, `（이름）`·`〈속마음〉`) → 한국어 학습자용, 185장
> - `english-cards/` — 영어 인터뷰(Vogue 73 Questions, 전문 캡션 `- [Name]`) → 한국어 학습자용, 248장
> - 리포 루트의 `index.html` = 관문 페이지. 앱을 만들면 그 `APPS` 목록에 한 줄을 더한다(§8-b).
>
> 새 콘텐츠를 만들 때는 **둘 중 자막 형식이 같은 쪽을 복사해서 시작**하는 것이 가장 빠릅니다.

---

## 0. 역할과 목표

당신은 어학 학습 콘텐츠 제작 에이전트입니다.
YouTube 영상 하나를 골라, 그 자막을 **대사 카드(원문 + 읽기 + 학습자 모어 번역)** 로 나누고,
영상 구간 재생·대본·표현/단어 학습·퀴즈·일일 분량이 붙은 **단일 HTML 앱**을 만듭니다.

입력으로 받는 것:
- 학습 대상 언어 L2 (예: 일본어), 학습자 모어 L1 (예: 한국어)
- 소재 조건 (예: "인기 아이돌 그룹 인터뷰 영상")
- 출력 폴더 (예: `dokadoka-cards/<name>-cards/`)

성공 조건:
1. `python3 src/build.py` 한 번으로 HTML 이 재생성된다 (외부 라이브러리 없이).
2. 모든 카드에 L1 번역이 있고, 카드 id ↔ 번역 id 가 전수 대응한다 (빌드가 assert 로 검사).
3. 브라우저에서 카드·대본·학습(오늘/표현/단어/퀴즈/학습법) 탭이 모두 렌더링되고 YouTube 구간 재생이 된다.
4. README 에 출처·재빌드 방법·구성이 적혀 있다.

## 1. 영상 고르기 (가장 중요한 단계)

### 1-1. 후보 검색
```bash
# 리포 루트(dokadoka-cards/)의 venv 에 yt-dlp 가 있다. 없으면: python3 -m venv .venv && .venv/bin/pip install yt-dlp
.venv/bin/yt-dlp "ytsearch8:<그룹명> インタビュー 公式" --flat-playlist \
  --print "%(id)s | %(duration)s | %(view_count)s | %(channel)s | %(title)s"
```
여러 검색어로 후보를 15~30개 모으고, **공식 채널 · 5~15분 · 대화 중심** 인 것만 남깁니다.

### 1-2. 지역 차단 확인 — 후보마다 반드시
`--list-subs` 가 `This video is not available` 을 내면 **일본 외 지역 차단**입니다. 자막을 못 받을 뿐 아니라 **사용자 브라우저에서도 재생이 안 되므로** 즉시 탈락시킵니다.
실제로 도라에몽·호빵맨·시마지로·포켓몬 Kids TV·페파피그 일본어·산리오·프리큐어의 공식 채널이 전부 이 경우였습니다.
(yt-dlp 가 JS 런타임 경고를 내면 `--js-runtimes node` 를 붙입니다. `-kzX…` 처럼 `-` 로 시작하는 ID 는 URL 앞에 `--` 를 둡니다.)

### 1-3. 자막 확인 — 후보마다 반드시
```bash
.venv/bin/yt-dlp --list-subs --skip-download "https://www.youtube.com/watch?v=<ID>"
```
판단 기준 (위가 좋음):

| 등급 | 자막 종류 | 비고 |
|---|---|---|
| A | **수동(공식) 자막** — `--list-subs` 에서 "has no subtitles" 가 없고 언어 행이 auto 와 별도로 뜸 | 화자명(`Name:`)·화면 자막(`［…］`) 이 붙어 있으면 최상 |
| B | 자동생성 자막, **2023년 이후** 업로드 | 인식 오류 소량, `fixes.txt` 로 교정 |
| C | 자동생성 자막, 2020년 이전 | 오류가 너무 많아 **사용 금지** (실제로 2018년 영상은 첫 줄부터 깨져 있었음) |

`INTERVIEW FOR THE FIRST TAKE` 처럼 자막이 아예 없는 공식 영상도 많습니다. 목록만 보고 결정하지 말고 **실제로 받아서 앞부분 40줄을 눈으로** 보세요.

**애니메이션 주의:** 아이 목소리·효과음 때문에 자동생성 자막 품질이 실사보다 훨씬 나쁩니다(페네로페는 첫 줄부터 깨짐, 짱구는 7분에 대사 79줄뿐). 애니는 **수동 CC 자막이 있는 영상만** 씁니다. 제목·설명에 「日本語字幕対応」이 있으면 유력합니다.

### 1-4. 받기
```bash
.venv/bin/yt-dlp --skip-download --write-subs --write-auto-subs --sub-langs "<L2코드>" \
  --sub-format srt --convert-subs srt -o "<scratch>/%(id)s.%(ext)s" "https://www.youtube.com/watch?v=<ID>"
```
- 수동 자막이 있으면 `--write-subs` 가 그것을 우선 받습니다.
- 자동생성 자막은 **큐가 겹쳐 굴러가는(rolling) 형식**일 수 있습니다. 앞 큐의 끝과 뒤 큐의 시작이 겹치면 그 형식이니 분할 단계에서 중복 제거가 필요합니다.
- 메타데이터도 함께 기록: `--print "%(title)s | %(duration)s | %(upload_date)s | %(channel)s | chapters=%(chapters)s"`. 공식 챕터가 있으면 장면 구분에 그대로 씁니다.

### 1-5. 분량 예상
카드 수 ≈ 대사 있는 큐 수 × 0.6~0.8. 8분 인터뷰 ≈ 80~110장, 27분 예능 ≈ 380장.
**100장 미만이면 사용자에게 분량을 먼저 알리고** 계속 진행합니다(길이보다 자막 품질이 우선).

## 2. 폴더 만들기

```
<name>-cards/
├─ <Lang>-<Nick><N>-Cards.html   앱 (build.py 가 생성; N = 카드 수)
├─ start.sh / start.bat          간이 서버 실행기 (포트는 기존 앱과 겹치지 않게: 8099, 8098, …)
├─ README.md
├─ WORKFLOW_PROMPT.md            (이 문서를 복사해 두면 다음 에이전트가 편함)
└─ src/
   ├─ subtitles.srt              원본 자막 (그대로 보관, 수정 금지)
   ├─ seg.py                     자막 → 카드 분할
   ├─ trim.py                    (자동생성 자막일 때만) 끝부분 무음 추정
   ├─ build.py                   최종 HTML 생성
   ├─ tpl.html                   화면 템플릿
   ├─ <l1>.txt                   번역(+읽기) `id|뜻|읽기|주석`
   ├─ fixes.txt                  (자동생성 자막일 때만) 인식 오류 교정 `id|교정문`
   └─ study.txt                  표현·단어 `종류|원문|읽기|뜻|메모`
```
기존 폴더에서 `src/tpl.html`, `build.py`, `start.*` 를 복사해 오되, **파일명·포트·LocalStorage 키(`LS`)·내보내기 파일명** 4곳은 반드시 바꿉니다. 키를 안 바꾸면 두 앱의 체크 진도가 섞입니다.

## 3. 분할 (seg.py)

목표: 큐(자막 한 줄)를 **한 호흡의 발화 = 카드 1장** 으로 묶기. id 는 시간순 1부터.

### 3-A. 공식 자막 (화자명 있음) — `japanese-cards/src/seg.py`
- 줄 분류: `Name: 대사` → 화자 있는 대사 / `-대사` → 화자 미상(한 큐에 여럿) / `［…］` → 화면 자막(대사 아님, 두 줄에 걸칠 수 있음) / 그 외 → 같은 큐 안 앞 대사의 연속.
- 병합: 같은 화자 · 간격 ≤ 0.35초 · 합쳐서 ≤ 34자 · 앞 문장이 `。！？` 로 안 끝날 때만.
- 화면 자막도 `spk='Cap'` 카드로 넣습니다(읽기 재료 + 타임라인 근거). 앱에서 옵션으로 뺄 수 있게 합니다.
- 화자 표기가 없는데 문맥상 명백한 줄은 `SPK_FIX = {원문: 화자}` 로 지정.

### 3-B. 방송용 CC 자막 (`（이름）`·`〈속마음〉`) — `yubisaki-cards/src/seg.py`
- `（雪）대사` 화자 태그는 **화자가 바뀔 때만** 붙습니다. 태그 없는 발화는 "직전에 태그가 붙은 *발화*(속마음 제외)의 화자"로 추정하고 `inf=1` 로 표시합니다.
- `〈…〉` 는 속마음. 태그가 없으면 주인공(`HERO`)의 것. 카드에 `th=1` 로 넣고 앱에서 칩·옵션으로 구분합니다.
- `（심장의 고동）` 류 효과음은 정규식(`音|鼓動|チャイム|メロディー|英語|振動|足音`)으로 걸러 버리고, `♪` 가사는 제외합니다.
- 한 큐에 두 화자(`（京弥）… （りん）ひいっ！`)가 있으면 태그 위치에서 조각을 나눕니다.
- 본문 후리가나 `橋元(はしもと)` 는 떼어 냅니다(읽기 줄에 넣음).
- **추정 화자(`*`)는 전수 검토**해 틀린 큐를 `SPK_FIX = {큐번호: 화자}` 로 고칩니다. 이번에는 40건 중 15건이 틀렸습니다(외국인의 "Bye bye", 이츠오미의 「飲む？ 飲まない？」, 린이 손윗사람에게 하는 인사 등 — 말투가 단서).

### 3-C. 영어 전문 캡션 (`- [Name] 대사` / `- 대사`) — `english-cards/src/seg.py`
- 미국 미디어 채널(Vogue·WIRED·GQ)의 공식 캡션은 `--list-subs` 에서 **자동 자막 목록의 `en-US` 행(vtt 만)** 으로 뜹니다. "Available subtitles" 가 비어 있어도 `--sub-langs en-US` 로 받아 보면 구두점·화자 태그·효과음이 붙은 사람이 만든 캡션입니다(등급 A). `en`/`en-orig` 는 자동 자막이니 섞지 마세요.
- `- ` 대시 = 새 발화. `[Interviewer]` 태그는 화자가 불분명할 때만 붙고, 태그 없는 대시는 **직전 화자의 상대**로 추정합니다(2인 인터뷰 전제, `inf=1`). 한 큐에 `- A / - B` 가 있으면 줄 단위로 나눕니다.
- 대시 없는 이어지는 줄인데 사람이 바뀌는 곳(`Let's do it. / And, I see …`)이 있으므로 **큐 번호가 아니라 줄 원문**으로 고칩니다(`LINE_FIX = {줄: 화자}`). 태그 오기(`Darrel`→`Darnell`)는 `ALIAS`.
- 답변 한 개가 200~400자로 길어지므로 `SPLIT_AT`(120자)에서 **문장 끝으로 나누고**, 시각은 줄 단위 큐 시각에서 글자 비율로 보간합니다. 그래도 39장이 생겼습니다.
- 영어는 읽기 줄이 없습니다. 템플릿의 읽기 UI·`R` 키·`optCap` 을 빼고, `ja`→`en` 은 `\bja\b` 정규식 한 번으로 바꿉니다(`edJa`·`ja2ko`·내보내기 파일명은 따로).
- 학습 항목 매칭은 단어 경계 + 굴절 접미(`-s/-ed/-ing/-er/-ly`) 허용 정규식입니다. `~` 로 나눈 조각 중 가장 긴 것을 찾습니다.

### 3-D. 자동생성 자막 (화자 없음) — `korean-cards/src/seg.py`
- 병합: 간격 > 1.0초면 끊고, 60자를 넘으면 문장 끝에서 끊음(96자 넘으면 강제).
- `[웃음]` `[음악]` 같은 태그는 빼고, 태그만 있는 큐는 카드에서 제외.
- `trim.py` 로 마지막 큐의 빈 시간을 글자밀도(4.5자/초)로 추정해 재생 종료점 `pe` 를 앞당김. **분할 로직을 seg.py 와 완전히 동일하게 유지**해야 id 가 어긋나지 않습니다(assert 로 검증).
- 문장 중간에서 잘린 카드는 나중에 `build.py` 의 `MERGES` 로 잇습니다. 분할 자체를 다시 하면 id 가 전부 밀려 번역이 깨집니다.

### 3-E. 출력 확인
```bash
python3 src/seg.py
python3 -c "import json; [print(c['id'], c.get('spk','-'), '|', c['ja']) for c in json.load(open('src/segs.json'))]"
```
**이 목록을 끝까지 읽고** 병합이 어색한 곳(다른 사람 말이 붙음, 한 문장이 둘로 갈림)이 있으면 임계값을 조정합니다. 번역을 쓰기 시작한 뒤에는 분할을 바꾸지 않습니다.

## 4. 번역·읽기 쓰기 (`<l1>.txt`)

형식 `id|뜻|읽기|주석` (읽기가 필요 없는 L2 면 빈 칸). 카드 전량을 **직접** 씁니다.

원칙:
- 뜻은 **말투를 살린 자연스러운 L1**. 반말은 반말로, 정중어는 정중하게. 직역이 아니라 그 장면에서 실제로 할 법한 말.
- 문장이 끊긴 카드(다음 카드로 이어짐)는 뜻도 끊긴 채로 둡니다. "…라서" "…하고" 처럼.
- 읽기(일본어의 경우): 전문 히라가나, **어절 단위 띄어쓰기**, 가타카나 어휘는 가타카나 유지, 숫자·영문은 발음대로(`2019.8.8` → `にせんじゅうきゅうねん はちがつ ようか`). 고유명사 읽기(인명·앨범명·관용 표현 `提げる=ひっさげる`)는 특히 확인.
- 주석: 문형·어휘 포인트 1개만 (`〜させていただく=(허락을 받아)〜하다, 겸양`). 없으면 비움. 절반 이상 채우는 것을 목표.
- 화면 자막 카드의 뜻은 정보 그대로(연도·행사명 유지).

### 4-b. 한자 풀이 사전 (일본어일 때, `words.txt` · `kanji.txt`) — `yubisaki-cards` 참고
뜻 영역에 카드의 한자어마다 **일본어 독음 · 한국 한자음 · 뜻 · 낱글자 훈음**을 자동으로 붙입니다.
- `kanji.txt`: `漢字|훈 음` (예 `曇|흐릴 담`). 카드에 나오는 한자 전부. 빌드 전에 `[一-鿿々]` 로 유일 한자를 뽑아 개수를 확인합니다(185장 ≈ 174자).
- `words.txt`: `어간(,여럿)|표제(사전형)|독음|뜻|한자음` (예 `変え|変える|かえる|바꾸다|변`). 어간은 **본문에 실제로 나오는 문자열**이고 긴 어간부터 맞춥니다. 같은 한자가 읽기에 따라 다른 말이면 오쿠리가나까지 어간에 넣습니다(生き物/生まれ, 降っ/降り, 変え/変).
- 빌드가 (1) 사전으로 덮이지 않은 한자 (2) `words.txt` 표제에 있는데 `kanji.txt` 에 없는 한자를 assert 로 잡습니다. 둘 다 비어야 합니다.
- 표현 풀이는 별도 데이터 없이 `study.txt` 의 E 항목 중 그 카드에 연결된 것을 템플릿이 보여 줍니다.

작성 후 반드시: 빌드가 `번역 없음: [...]` / `카드에 없는 id: [...]` 로 대응을 검사합니다. 그 다음 **표본 8장 이상을 원문 옆에 나란히 출력해** 밀림이 없는지 눈으로 확인합니다.

## 5. 학습 데이터 (`study.txt`)

형식 `E|표현|읽기|뜻|메모` (문형·관용구), `V|단어|읽기|뜻|메모`. 목표 80~130건(표현 40% / 단어 60%).

- 후보는 **자막에 실제로 나온 것만**. 빌드가 각 항목이 등장하는 카드 id 를 자동으로 찾아 예문·클립을 연결합니다.
- 매칭 규칙(`build.py find_hits`): 원문 그대로 → 없으면 `〜` 앞부분 → 끝에서 최대 3자까지 떼어 가며 재시도(`諦める`→`諦め`→`諦めてません` 매칭). 한 글자 항목은 한자일 때만 허용. 한국어처럼 조사가 붙는 언어는 `korean-cards` 의 조사 목록 방식을 씁니다.
- 빌드 출력의 `0개: …` 가 **비어야** 합니다. 남으면 표제어를 자막에 나온 형태로 바꾸거나 규칙을 손봅니다.
- 빌드 후 `hit ≠ 표제어` 인 항목과 매칭 4건 이상 항목을 출력해 오탐(`運`이 `運動`에 걸리는 류)을 점검합니다.

## 6. build.py 에서 정하는 것

- `VID` — 영상 ID.
- `SCENES` — `(키, 시작초, L1 라벨, L2 라벨)`. 근거 우선순위: 공식 챕터 > 화면 자막(연도·행사) > 내용 전환. 추측으로 만들지 않습니다.
- `SPEAKERS` — 자막의 화자 키 → `(L2 표기, L1 표기, 멤버 여부)`. `Fan`/`Fans` 처럼 같은 뜻은 앱에서 하나로 묶입니다.
- `MERGES` / `fixes.txt` — 자동생성 자막일 때만.
- 마지막에 카드 수·장면별·화자별 분포를 출력하게 두고, **0장인 장면이 없는지** 봅니다.

## 7. 템플릿 (tpl.html) 규칙

- UI 는 **L1 이 주, L2 가 부**(`bi(l1, l2)`), 카드 본문만 L2. 기존 템플릿을 뒤집어 쓸 때 `lang` 속성도 함께 바꿉니다.
- 데이터 키는 언어 코드 그대로(`ja`/`ko`/`rd`)가 헷갈리지 않습니다.
- 필수 기능 목록(둘 다 갖춰야 함): 카드(장면·화자 칩, 뜻 가리기, 읽기 토글, 체크, 편집, 내보내기/가져오기) · 대본(클릭 재생·자동 추종) · 학습(오늘/표현/단어/퀴즈/학습법) · 구간 재생(앞뒤 여유, 반복, 자동 다음) · `file://` 폴백(YouTube 새 탭).
- 학습 탭의 **오늘** 페이스 값은 카드 수에 맞춥니다(383장: 20/28/40/55, 105장: 10/15/21/35 → 각각 14일·7일 완성).
- 학습법 탭의 팁은 소재에 맞게 고쳐 씁니다(자동생성 자막이면 "자막은 완벽하지 않다", 공식 자막이면 대신 "한자는 읽기부터" 등). 반말/정중어 팁은 **그 영상의 실제 대사**를 예로 듭니다.
- 두 앱의 템플릿이 갈라지기 쉽습니다. 작업 시작 전에 참조 앱의 `tpl.html` **수정 시각을 확인**하고, 이미 읽은 뒤 바뀌었으면 다시 읽습니다(이번에 실제로 학습 탭이 중간에 바뀌어 재이식했습니다).

## 8. 실행기와 README

### 8-a. 앱 폴더

- `start.sh`: `python3 -m http.server <PORT>` + 브라우저 열기, 포트 충돌 시 +1.
- `start.bat`: CRLF 로 저장(`sed -i 's/$/\r/'`), UNC 경로·Python 없음·파일 없음 3가지 안내 분기, `set PAGE=` 에 파일명.
- README: 실행 방법 / `file://` 제한(Error 153) / 기능 / 구성 트리 / 재빌드 / 다른 영상으로 바꾸는 법 / 출처(영상 ID·채널·업로드일·자막 종류) / "학습용 개인 이용" 문구.

### 8-b. 관문 페이지에 등록 (리포 루트 `index.html`)
- 루트의 `index.html` 은 **일본어 학습 앱**의 관문입니다(한국어 학습 앱은 싣지 않는다 — 사용자 지시). 루트 `start.sh`/`start.bat`(포트 8100)이 폴더 전체를 서빙하므로 각 앱은 `폴더/파일.html` 상대 경로로 열립니다.
- 앱을 만들면 `APPS` 배열에 한 줄을 더합니다: `vid`(썸네일용 영상 ID) · `href`(상대 경로) · `learn`(`ja`/`ko`/`en` — 언어 섹션이 자동으로 나뉨) · `kind` · `title` · `src`(채널·연월·길이, 마지막 `·` 뒤가 길이 배지) · `desc` · `cards` · `level` · `sub`(자막 종류) · `extra`.
- 새 폴더에 `WORKFLOW_PROMPT.md` 를 두지 않아도 됩니다. 정본은 `japanese-cards/WORKFLOW_PROMPT.md` 하나이고, 이 파일을 갱신합니다.

## 9. 검증 (건너뛰지 말 것)

1. **빌드** — `python3 src/build.py` 가 번역 대응·중복 assert 를 통과하고 `0개: 없음` 이 출력된다.
2. **JS 문법** — HTML 에서 `<script>` 안쪽을 잘라 파일로 저장한 뒤 `node --check <파일>`.
   ```bash
   python3 -c "import re;h=open('<앱>.html',encoding='utf-8').read();open('<scratch>/app.js','w').write(re.search(r'<script>\n(.*?)</script>',h,re.S).group(1))"
   node --check <scratch>/app.js
   ```
3. **헤드리스 렌더** — playwright 캐시의 Chromium 을 직접 실행합니다. 반드시 **http 서버 뒤에서** 찍습니다(`file://` 는 YouTube 가 막힘).
   ```bash
   python3 -m http.server 8098 >/dev/null 2>&1 & SRV=$!; sleep 1
   ~/.cache/ms-playwright/chromium-*/chrome-linux*/chrome --headless=new --no-sandbox --disable-gpu \
     --window-size=1500,1000 --virtual-time-budget=6000 --screenshot=<scratch>/card.png \
     "http://localhost:8098/<앱>.html"
   kill $SRV
   ```
   - 학습 탭은 사본 HTML 끝에 `switchView('study')`(학습법은 `setSub('G')` 추가)를 붙여 같은 방법으로 찍습니다.
   - `--dump-dom` 으로 `totalCount`·`pos`·`playStatus`("준비 완료")·대본 줄 수·학습 행 수를 grep 해 숫자를 확인합니다.
   - 스크린샷은 **직접 열어서** 봅니다(플레이어 로드, 읽기 줄, 칩, 사이드바 목록).
   - 서버를 끝낼 때 `pkill -f http.server` 는 실행 중인 셸까지 끊을 수 있으니 PID 로 `kill` 합니다.

## 10. 사용자에게 열어 줄 때 (WSL 환경)

```bash
nohup python3 -m http.server 8098 --bind 0.0.0.0 >/dev/null 2>&1 &
powershell.exe -NoProfile -Command "Start-Process 'http://$(hostname -I | awk '{print $1}'):8098/<앱>.html'"
```
`localhost` 가 아니라 **WSL IP** 로 엽니다(nat 모드에서는 Windows→WSL localhost 포워딩이 불안정). 서버는 재빌드 후에도 그대로 두면 새로고침만으로 반영됩니다.

## 12. 이번 작업에서 실제로 걸린 것들 (재발 방지)

1. 인기 있는 영상 ≠ 자막 좋은 영상. THE FIRST TAKE 인터뷰(82만 뷰)는 자막이 없고, 2018년 공식 Q&A(250만 뷰)는 자동자막이 못 쓸 수준이었다. **공식 자막 유무가 결정 기준.**
2. 참조 템플릿이 작업 도중 바뀌었다. 복사본을 만들기 전에 mtime 을 보고, 끝나기 전에 한 번 더 diff.
3. 학습 항목은 사전형으로 적으면 활용형과 안 맞는다. 어간 매칭 규칙을 넣고 `0개` 목록을 빈 상태로 만들 것.
4. 헤드리스 Chrome 은 `file://` 로 열면 YouTube 가 막히므로 반드시 http 서버 뒤에서 찍는다.
5. 한 글자 표제어(`姿`)는 한자만 허용. 가나 한 글자는 오탐.
6. 자동생성 자막의 `pe`(무음 컷)와 `MERGES` 는 id 를 바꾸지 않는 후처리로만 한다.
7. 아동용·공식 애니 채널은 대부분 일본 외 지역 차단. "not available" 은 yt-dlp 고장이 아니라 지역 차단이므로 알려진 정상 영상으로 한 번 대조한 뒤 후보를 버린다.
8. 애니 자동자막은 실사보다 훨씬 나쁘다. 수동 CC 가 있는 영상만 쓴다.
9. CC 자막의 화자 태그는 "바뀔 때만" 붙는다. 추정 화자를 전수 검토하지 않으면 사람이 바뀐 대사가 섞인다.
10. 미국 미디어 채널의 공식 영어 캡션은 yt-dlp 가 자동 자막 목록에 `en-US`(vtt) 로 끼워 보여 준다. "has no subtitles" 만 보고 자동 자막(`en`)을 쓰면 구두점·화자가 전부 사라진다. `en-US` 를 받아 앞 40줄을 눈으로 볼 것.
11. 영어 인터뷰 답변은 한 호흡이 길어 큐 병합만으로는 300자 카드가 나온다. 문장 끝 분할 + 줄 단위 시각 보간이 필요했다.
12. 관문 `index.html` 은 2026-09-11 오후에 한때 「일본어 전용」으로 좁혀졌다가, 같은 날 사용자 요청으로 **일본어·한국어·영어 3개 언어 섹션**으로 다시 확장됐다. 새 앱은 `APPS` 에 `learn: 'ja'|'ko'|'en'` 으로 한 줄 추가하면 해당 언어 섹션에 실린다.
13. 긴 문서를 셸 히어독으로 쓸 때 본문에 같은 종료 마커(`EOF`)가 들어 있으면 중간에 끊긴다. 문서는 파일 쓰기 도구로 저장한다.
