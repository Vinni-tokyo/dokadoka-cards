# 학습 탭 UX 개선 계획 — 일본어 토크쇼 앱 · 일본어 노래 앱 (2026-09-13)

시안(HTML): `docs/ux-mockup-2026-09-13.html` (Artifact 로도 게시)

## 1. 대상 콘텐츠

| 구분 | 앱 | 선정 이유 |
|---|---|---|
| 일본어 학습 | `mika-cards` 성시경의 만날텐데 × 나카시마 미카 (640장, 표현 45 · 단어 28, 25일 분량) | 카드가 가장 많고 2인 대화라 「오늘」 분량·드릴·퀴즈 등 학습 탭의 모든 단계가 실제로 쓰인다. 공식 수동 자막이라 데이터 품질 문제가 없어 UI 문제만 분리해 볼 수 있다. |
| 일본어 노래 | `firstlove-cards` 宇多田ヒカル「First Love」 (28줄, 노래방 · 마디 반복 · BPM 그리드) | 노래 앱 4종 중 마디 반복 컨트롤이 가장 많이 쓰이는 곡이고, 방금 루프 되감김 문제를 고쳐 재생 쪽은 안정된 상태. 남은 문제는 순수 UI. |

두 앱 모두 `src/tpl.html` 이 다른 앱과 공유되는 계열 템플릿이므로, 여기서 정한 개선은 일본어 앱 6종 · 노래 앱 4종에 같은 패치로 번진다.

## 2. 현재 문제 (헤드리스 스크린샷 1400px · 390px 근거)

### 공통 (PC · 모바일)

1. **학습 단계 이름이 세 군데에서 다르다.**
   하위 탭 = 드릴·오늘·표현·단어·퀴즈·학습법 / 「오늘」 탭 띠 = 듣기 › 표현·단어 › 퀴즈 › 복습 / 「학습법」 탭 = 듣기 › 확인 › 따라 하기 › 점검.
   학습자는 「지금 몇 단계인지」를 어디서도 확정할 수 없다.
2. **「오늘」의 4단계 띠가 장식이다.** 누를 수 없고 완료 표시도 없다. 「완료」 버튼은 Day 전체를 수동 체크할 뿐이다.
3. **드릴 설정이 매번 12개 컨트롤(4줄)이다.** 범위·방식·크기·음성·속도·자동 읽기·반복 횟수·뜻과 함께. 「시작」이 맨 아래라 첫 화면 밖으로 밀린다(모바일).
4. **드릴 채점 버튼이 카드 아래에 있다.** 모바일 390px 에서는 예문 아래로 밀려 화면 밖. 스크롤해야 「몰라·애매·알아」를 누를 수 있다. 터치 기기에서는 키보드 힌트가 숨겨져 다른 방법도 없다.
5. **「듣기」 단계가 학습 탭 밖에 있다.** 「카드로」를 누르면 카드 뷰로 나가고, 오늘 분량 필터만 걸린 채 돌아오는 길이 없다.
6. **드릴 결과(SRS lv·due)는 저장되지만 다음 날 행동으로 이어지지 않는다.** 「오늘 복습 N」 숫자만 있고 오답 → 복습 연결은 학습법 본문에만 적혀 있다.

### 모바일 (390px)

7. **플레이어가 학습 뷰에서도 상단 210px 를 차지한다.** 드릴·퀴즈는 영상을 쓰지 않는데 학습 콘텐츠가 첫 화면의 절반 아래에서 시작한다.
8. **하위 탭 6개가 두 줄로 감싸지고** 폭이 들쭉날쭉하다.
9. **Day 띠 25개 버튼이 한 줄에 눌려 숫자가 겹친다** (「1011121314…」로 읽힘).

### 노래 앱

10. **학습 탭·학습법이 토크쇼용 복사본이다.** 「반복 C」·「퀴즈」·「카드」 용어 그대로. 노래에 필요한 단계(들으며 읽기 → 마디 따라 부르기 → 가사 가리고 부르기)가 없다.
11. **마디 반복 패널이 13개 컨트롤 한 상자다.** 1/2/4/8마디 · 이 줄의 마디 · ◀ ▶ · ±1마디 · 정지 · 속도 3개 · ±1박. 모바일에서 4줄. 게다가 **노래방 탭에는 이 패널이 없어서** 가사를 보며 반복하려면 카드 탭과 노래방 탭을 오가야 한다.
12. 노래방 뷰의 가리기 옵션이 「읽기·뜻」 체크박스뿐이라 **외우기 단계(가사 가리기)가 없다.**

## 3. 설계 원칙

- **단계 하나 = 화면 하나.** 세션은 「오늘」 홈에서 시작해 홈으로 돌아온다. 단계 이름은 학습법의 4단계(듣기·확인·따라 하기·점검)로 통일한다.
- **설정은 접는다.** 기본값으로 즉시 시작. 음성·속도·반복 횟수는 앱 전역 설정으로 한 번만 정한다.
- **판정은 엄지 영역.** 모바일에서 채점·다음 버튼은 하단 고정 바. 카드 본문은 위.
- **진행이 보인다.** 단계별 완료 체크, 연속 학습일, 복습 대기 수를 홈에서 바로 본다.
- **영상은 필요한 단계에서만.** 학습 탭의 모바일 플레이어는 미니 바(제목 · 재생/일시정지)로 접고, 듣기·따라 하기 단계에서만 펼친다.

## 4. 제안

### A. 일본어 학습 앱 (mika 계열) — 학습 탭 재구성

- 하위 탭 6 → 4: **오늘 · 복습 N · 목록 · 학습법**. 드릴·퀴즈·표현·단어는 탭이 아니라 단계 안에서 호출한다(목록 탭은 표현+단어 통합 검색).
- **「오늘」 홈 = 4단계 스테퍼 카드.** 각 카드에 제목(한·일), 분량, 예상 시간, 상태(미시작 / 진행 n/총 / 완료), 버튼 하나(시작 · 이어서 · 다시).
  1. 듣기 聞く — 오늘 대사 26장을 뜻 가린 채 재생. 학습 탭 안의 「세션 모드」(상단 진행 띠 12/26, 끝나면 다음 단계 제안).
  2. 확인 確かめる — 표현 2 · 단어 2 미니 드릴(日→韓, 뜻과 함께, 예문 재생).
  3. 따라 하기 真似る — 체크한 대사·표현 예문 구간을 3회 자동 반복. 「따라 말했다」 버튼으로 진행.
  4. 점검 試す — 오늘 분량 퀴즈 10문항. 오답은 복습 큐로.
- 상단: DAY n/25, 페이스, 연속 학습일, 복습 대기 배지. Day 띠는 가로 스크롤 + 현재 중앙 정렬 + 완료 색. 모바일은 「‹ DAY 3 ›」 + 진행 바.
- **복습 탭**: SRS 기한 도래 항목 + 퀴즈 오답 + 체크 카드를 한 목록으로, 「복습 시작」 버튼 하나(드릴 韓→日 / 듣기 자동).
- **드릴·퀴즈 설정 접기**: 「설정 ⚙ 표현 · 日→韓 · 20개」 한 줄 요약, 펼치면 기존 컨트롤.
- **드릴 카드(모바일)**: 카드 위, 하단 고정 바(답 보기 → 몰라·애매·알아). 예문은 접힌 칩. 스와이프 좌(몰라)/우(알아)는 선택 옵션.
- **PC**: 왼쪽 플레이어, 오른쪽 스테퍼. 드릴 카드는 폭 640px 로 좁혀 읽기 65자 유지. 키 1·2·3·Space·R 힌트는 유지.

### B. 일본어 노래 앱 (First Love 계열)

- **노래 4단계**(학습법 텍스트도 노래용으로 교체):
  1. 들으며 읽기 — 노래방 뷰, 읽기·뜻 ON, 전곡 1회. 끝까지 재생하면 완료.
  2. 마디 따라 부르기 — 절·후렴 단위로 2 → 4 → 8마디 루프, 속도 0.75 → 1×. 줄을 탭하면 그 줄의 마디부터.
  3. 가사 가리고 부르기 — 뜻 OFF → 읽기 OFF → 가사 첫 글자만 표시. 줄마다 「불렀다」 체크.
  4. 표현·단어 — 25 · 20 드릴과 퀴즈(기존).
- **마디 반복 패널을 노래방 뷰 하단 바로 통합**. 1줄: 루프 길이 1·2·4·8 | 속도 0.5·0.75·1 | ◀ ▶ | 정지. ±1마디·±1박 보정은 「미세 조정 ▾」 안으로. 모바일은 하단 고정.
- 노래방 가사에 **루프 범위 하이라이트**(마디 17–20 · 0:42–0:53 · 3회째)와 박 점 4개를 같이 표시.

## 5. 구현 단계

| 단계 | 대상 템플릿 | 내용 | 검증 |
|---|---|---|---|
| P1 공통 (효과 가장 큼) | 일본어 앱 6종 + 노래 앱 4종 `src/tpl.html` | 모바일 플레이어 미니 바 · 하위 탭 4개 · 드릴 하단 고정 채점 바 + 설정 접기 · Day 띠 가로 스크롤 | 390/1400px 헤드리스 스크린샷, 채점 버튼이 첫 화면 안에 있는지 DOM 좌표 확인 |
| P2 토크쇼 계열 | mika · frieren · milky · hatsukoi · yubisaki · bokuyaba | 「오늘」 홈 스테퍼 + 단계 상태 저장(`stage.{day}.{n}`) · 듣기 세션 모드 · 복습 탭 | 단계 완료 → 다음 단계 제안 → Day 완료 자동 체크 흐름, 기존 localStorage(체크·SRS·편집) 호환 |
| P3 노래 계열 | firstlove · reasons · vitaminme · saranghagi | 노래 4단계 홈 · 마디 바 노래방 통합 · 가사 가리기 모드 · 노래용 학습법 | 마디 루프 되감김 테스트 11건 회귀 없음, 가리기 3단계 스크린샷 |

각 단계는 템플릿 하나를 고치고 `build.py` 로 전 앱을 다시 만든 뒤 스크린샷으로 확인한다. 데이터(`ko.txt`·`study.txt`·음원)는 손대지 않는다.

## 6. 결정이 필요한 것

1. 드릴·퀴즈를 하위 탭에서 완전히 빼도 되는지(단계 안에서만 호출) — 시안은 뺀 안.
2. 드릴 스와이프 채점(좌 몰라 / 우 알아)을 넣을지 — 오터치 위험이 있어 기본 OFF 옵션 제안.
3. 노래 3단계 「가사 가리기」에서 첫 글자만 남기는 규칙(어절 첫 글자 vs 줄 첫 글자).
4. P1 을 10개 앱 전부에 한 번에 적용할지, mika · firstlove 2개로 먼저 검증할지 — 2개 먼저를 권장.

## 7. 더 멀리 — 세계 최고 수준을 기준으로 다시 본 개선안 (2026-09-13 추가)

앞의 1~6절은 「지금 있는 기능을 바르게 배치」하는 안이다. 이 절은 최고 수준의 언어 학습 제품이 당연히 갖춘 것을 기준으로, 이 앱에 **없는 것**을 찾은 결과다. 단일 HTML 파일 · 서버 없음 · YouTube 임베드라는 제약 안에서 실제로 구현 가능한 것만 골랐다.

### 7.1 확인된 현재 상태 (코드 grep 근거)

| 항목 | 현재 | 세계 최고 제품 |
|---|---|---|
| 복습 스케줄 | 고정 사다리 `INTERVALS=[0,1,3,7,14]`, 5단계 | FSRS(기억 확률 모델, Anki 기본 채택) |
| 읽기 표시 | 문장 아래 히라가나 한 줄 | 한자 위 루비 + 단어별 피치 액센트 선 (OJAD · Migaku) |
| 단어 사전 | 별도 목록 탭에서 검색 | 문장 속 단어 탭 → 팝오버, 단어 상태 3색(모름·학습중·앎) (Language Reactor · LingQ) |
| 퀴즈 | 4지선다 3종(日→韓·韓→日·듣기) | 받아쓰기 · 빈칸(cloze) · 타이핑 산출 (Anki · Bunpro) |
| 발화 훈련 | 구간 반복만 | 녹음 → 원음과 A/B 비교, 파형 (Speechling · Pimsleur) |
| 재생 속도 | 노래 앱만 (토크쇼 앱 `setPlaybackRate` 0회) | 0.75× 기본 제공, 모르면 자동 감속 |
| 오프라인 · 설치 | 3.4MB 단일 파일, 매번 다운로드 | PWA(Service Worker 캐시, 홈 화면 설치) |
| 이어폰 · 잠금화면 | 없음 | Media Session API(이어폰 버튼 다음·반복), Wake Lock |
| 다크 모드 | 없음 (`prefers-color-scheme` 0회) | 시스템 연동 |
| 앱 간 진행 | 허브에 없음 | 오늘 할 일 · 복습 대기 · 스트릭 합산 대시보드 |
| 측정 | 없음 | 세션 완료율 · 카드당 탭 수 · 첫 재생까지 시간 |

### 7.2 Tier 1 — 학습 효과에 직결 (모두 클라이언트만으로 가능)

1. **FSRS 스케줄러**. 카드마다 안정도·난이도·기억 확률을 계산해 「오늘 복습」을 정한다. 기존 `dState{lv,due,miss}` 는 1회 마이그레이션. JS 200줄 안팎, 외부 서비스 불필요.
2. **루비 후리가나 + 피치 액센트**. fugashi 토큰별 `kana` · `aType` 이 이미 나온다(本当⓪ おっしゃる③ 通り③ テレビ①). 빌드 타임에 `<ruby>` 와 액센트 선(고→저 꺾임)을 생성. 읽기 줄은 「루비 끄기」로 대체. 노래 앱은 원곡 억양이 우선이므로 표시만 하고 강조하지 않는다.
3. **문장 속 단어 탭 → 사전 팝오버 + 단어 상태 3색**. `words.txt` · `kanji.txt` 가 이미 100% 커버. 단어별 「모름·학습중·앎」을 저장하면 **카드마다 모르는 단어 수**가 나오고, 그 값으로 오늘 분량을 「i+1」(모르는 단어 1개짜리 문장 먼저) 순으로 정렬할 수 있다.
4. **받아쓰기 · 빈칸 퀴즈**. 듣고 타이핑(히라가나·한자 모두 정답, 부분 점수), 조사 빈칸(が·は·に·で), 노래는 가사 빈칸. 현재는 인식(recognition) 훈련만 있고 **산출(production) 훈련이 0** 이다.
5. **섀도잉 녹음 · 비교**. MediaRecorder 로 내 목소리를 녹음해 원음 · TTS 와 번갈아 재생, 파형을 겹쳐 길이 · 끊김 위치를 비교. IndexedDB 에 로컬 저장, 서버 전송 없음. 피치 곡선 비교는 2차.
6. **토크쇼 앱 재생 속도**. 0.75 · 0.85 · 1.0×, 「몰라」 채점 시 다음 재생을 자동으로 느리게.
7. **3분 마이크로 세션 + 종료 보고**. 한 세션을 3분 단위로 자르고 끝에 「들은 문장 12 · 새로 안 단어 4 · 내일 복습 7 · 연속 5일」을 보여 준다.

### 7.3 Tier 2 — 속도 · 품질 · 접근성

8. **PWA + Service Worker**. 첫 방문에 캐시하면 이후 즉시 기동 · 오프라인(YouTube 만 온라인). 홈 화면 설치 아이콘. 음원은 이미 파일 안에 있으므로 추가 작업 없음.
9. **Media Session + Wake Lock + 오디오 전용 모드**. 잠금화면에서 다음 · 반복, 이어폰 버튼 대응, 섀도잉 중 화면 꺼짐 방지. 「걸으며 듣기」 = 문장 TTS → 뜻 TTS → 다음(기존 자동 반복 듣기 확장).
10. **다크 모드 + 접근성**. 시스템 연동 다크, 채점 결과 `aria-live`, 터치 타겟 44px, PC 단축키 한 벌로 통일(J/K 이전·다음, Space 재생, 1·2·3 채점, R 루비, C 반복).
11. **30초 온보딩**. 처음 열면 「오늘 5분 시작」 버튼 하나. 음성 · 속도 설정은 첫 드릴 뒤에 한 번 묻는다.
12. **허브 대시보드**. 모든 앱이 같은 오리진(vinni-tokyo.github.io)이라 허브 `index.html` 이 각 앱의 localStorage 를 읽을 수 있다. 「오늘 할 일 · 복습 대기 합계 · 스트릭 · 마지막 학습」을 앱 목록 위에 한 줄로. 전체 진행 JSON 내보내기 · 가져오기(기존 편집 내보내기를 확장).
13. **문장 채굴 내보내기**. 체크한 카드 + 음원을 Anki 용 TSV 로.

### 7.4 Tier 3 — 측정으로 만드는 품질 루프

14. **로컬 사용 로그**. 재생 · 채점 · 이탈 시각을 localStorage 에 기록(외부 전송 없음) → 「학습 리포트」 화면: 세션 완료율, 카드당 탭 수, 첫 재생까지 시간, 요일별 학습량.
15. **빌드 시 UX 회귀 검사**. 헤드리스로 390 · 1400px 스크린샷 + 규칙 검사(첫 재생까지 탭 ≤ 2, 채점 버튼이 뷰포트 안, 본문 가로 스크롤 0).
16. **데이터 품질 게이트 전 앱 적용**. 자막 시작 보정(`align_start.py`) · 한자 100% 커버 검사 · 읽기 오류 목록을 모든 앱 빌드에 강제.
