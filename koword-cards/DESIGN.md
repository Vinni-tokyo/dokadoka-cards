# 도카도카 한국어 단어·표현 카드 · 설계서

> 한국어 영상 앱 6편에서 나온 단어·표현만 모아 따로 외우는 학습툴. **v1 은 만들었으나 화면이 어색하다는 지적을 받고**
> 한자 카드 앱(`kanji-cards`)을 다시 분석해 다시 설계한다. 2026-09-14.

---

## 1. 무엇이 어색한가 (실측 대조, 2026-09-14)

v1 을 만들 때 한자 앱의 **README 만 읽고 화면 코드를 보지 않았다.** 그래서 회독·덱 같은 *개념*은 옮겨왔는데
*손에 닿는 부분*이 전부 달라졌다. 두 `tpl.html` 의 CSS 를 직접 대조한 결과:

| 요소 | 한자 카드 | v1 (내가 만든 것) | 결과 |
|---|---|---|---|
| 헤더 | `background:var(--brand)` 남색 띠 · `44px │ 1fr │ 44px` 3칸 그리드 · 가운데 제목+부제 | 흰 배경 `flex` · 왼쪽 정렬 · 뒤로가기만 | **앱이 아니라 설정 폼처럼 보인다** |
| 카드 표제 | `clamp(56px, 20vw, 84px)` · `color:var(--brand)` | `clamp(28px, 8vw, 42px)` · 본문색 | **주인공이 절반 크기**. 플래시카드인데 단어가 안 튄다 |
| 두 버튼 | `height:64px` · `border-radius:32px` · `box-shadow:0 4px 0` · 누르면 내려앉음 | `padding:14px` · `radius:12px` · 평면 | **엄지로 누르는 물건처럼 안 생겼다** |
| 앞/뒷면 | 같은 마크업에 `visibility:hidden` (`.hid`) | 뒷면 내용을 **추가**로 붙임 | **뜻을 열면 글자가 튄다** |
| 장 고르기 | `.chs` 격자 — 장마다 칸, 끝난 장/하는 장 색 구분 | 없음. 덱을 누르면 **무조건 1장부터** | **어디까지 했는지 안 보이고 고를 수도 없다** |
| 장 크기 | 칩 `15 · 20 · 30 …` | `<input type=range>` 슬라이더 | 모바일에서 숫자를 정확히 맞추기 어렵다 |
| 관문 복귀 | 헤더에 `⌂메인` + 하단에 텍스트 링크 | **없음** | **막다른 길.** 다른 앱으로 갈 수 없다 |
| 노치 | `env(safe-area-inset-top/bottom)` | 없음 | 아이폰에서 헤더·버튼이 잘린다 |
| 화면 수 | 7 (홈·카드·결과·복습함·듣기설정·듣기재생·소리가족) | 4 (홈·카드·결과·목록) | — |

**핵심 진단** · 개별 결함의 합이 아니다. 한자 앱은 **「덱 → 장 → 카드」 3단계**인데 v1 은 **「덱 → 카드」 2단계**다.
장을 건너뛴 탓에 *진도*라는 감각이 사라졌고, 그 위에 헤더·버튼·표제까지 작고 평평해서 **학습 도구가 아니라 목록 뷰어**가 됐다.

## 2. 그대로 이어받을 것 (같은 사이트의 앱이므로)

- 색 토큰 `--brand #3b4a7a` · `--accent #b0603f` · `--know` · `--study`, 다크 모드 블록
- `.app{max-width:520px}` 모바일 1열, `100dvh`, `.view.on` 전환
- **남색 헤더 + 3칸 그리드**, 그 아래 `--brand2` 부제 띠(번호 · 공부시간)
- **하단 고정 두 버튼** 64px · 반경 32 · 입체 그림자 · `? 공부하겠음` / `✓ 알고있음`
- **`.hid` 자리 고정** — 앞면에서도 뒷면 요소가 자리를 차지하고 `visibility:hidden` 만. 넘길 때 화면이 안 튄다
- 덱 행 `54px │ 1fr │ 진행` 3칸, 장 격자 `.chs`, 장 크기 칩, 세그먼트 전환
- `⌂메인` 링크(헤더 + 하단), 내보내기/가져오기/초기화, 빌드 시각, 자료 출처 문단
- 회독 규칙: 1회독 전부 → 2회독부터 「공부하겠음」만 → 0장이면 그 장 완료

## 3. 한국어라서 달라야 하는 것

한자 앱을 그대로 베끼면 안 되는 지점이 셋 있다. 언어가 다르기 때문이다.

| 한자 앱 | 한국어 앱 | 이유 |
|---|---|---|
| 단어 카드 / **한자 카드** 2종 | **표현 카드 / 단어 카드** 2종 | 한국어에 낱글자 단위 학습 대상이 없다. 대신 `-거든요` 같은 **문형**이 그 자리 |
| 급수 = JLPT N5~N1 (외부 목록) | **없다** → 사이트 등장 빈도 | TOPIK 급수 목록을 오프라인으로 구할 수 없다. 한자 앱도 초안은 빈도 5등급이었다 |
| 상세 = 부수·획수·구성·획순 | **발음 · 문형 · 나온 곳** | 한글은 획순을 외울 필요가 없다. 대신 **철자≠소리**가 한국어의 진짜 벽 |

**한자어 대응(활동=活動)은 v1 에서 검토했다가 버렸다.** 단어 261개에 자동 대응을 시도하니
`하루=一日` `오늘=今日` `바람=風` 처럼 **고유어에까지 짝이 붙었고**, 사전 검증을 통과한 것은 114개 중 36개뿐이었다.
틀린 어원을 가르치게 되므로 제외한다. 되살리려면 손으로 검증한 목록이 필요하다.

**발음이 그 자리를 대신한다.** 455개에 표준발음법 규칙(연음·겹받침·ㅎ축약/탈락·비음화·유음화·경음화·구개음화)을 적용해
**소리가 달라지는 81개(18%)** 를 찾았다. 표준 예제 39개 중 37개 일치. 못 하는 둘은 규칙이 아니라 사전이 필요한 것이다
— 합성어 경계(`한여름`[한녀름])와 한자어 경음화(`활동`[활똥]). 실패 방향이 **덜 적용하는 쪽**이라 없는 소리를 지어내지는 않는다.

### 4-3. 결과 · 복습함 · 목록

- **결과** — 한자 앱과 동일(큰 숫자 · 알고있음/공부하겠음 · 다음 장 / 회독 / 홈).
- **복습함** — 「공부하겠음」 누적. 여기서 바로 카드로. *v1 에 없던 화면.*
- **목록·검색** — 455개를 한국어·일본어·주석으로 찾고 표현/단어/발음/표시로 거른다. *한자 앱에 없는, 이 앱의 강점.* 헤더 돋보기로 진입.

| 표시 | 덱이 달라도 **카드 단위로 기억**(작품 덱에서 안 것은 표현 덱에서도 앎) |
| 저장 | `localStorage['koword-cards']` 한 키 · 내보내기/가져오기 JSON |

## 6. 완료 기준 (검증 가능한 것만)

1. 412px 폭에서 카드 화면이 **스크롤 없이** 들어가고 가로 넘침 없음.
2. 앞면 → 뒷면 전환 때 **표제의 세로 위치가 1px 도 움직이지 않음**(`.hid` 자리 고정 확인).
3. 덱을 누르면 장 격자가 펼쳐지고, 끝낸 장·하는 장이 색으로 구분됨.
4. 1장을 끝까지 돌렸을 때 결과의 합이 그 장 카드 수와 같고, 2회독에 「공부하겠음」 수만큼만 남음.
5. 헤더 `⌂메인` 이 `../index.html` 로 가고, 「▶ 장면」이 해당 영상 앱의 그 대사를 연다.
6. 하단 두 버튼이 64px 이고 `env(safe-area-inset-bottom)` 이 적용됨.
7. **없는 id 에 `null` 을 돌려주는 하니스**로 6개 덱 전부 카드·버튼이 그려짐
   (v1 에서 `textContent` 가 자식을 지워 화면이 비었던 사고의 재발 방지).
8. `node --check` 통과, 관문에서 열림.

## 7. v1 에서 가져갈 것 / 버릴 것

**가져간다** — 데이터 파이프라인(`build.py` 455개 집계·중복 병합), 발음 엔진(`pron.py`, 자체 검증 39예제),
예문·장면 링크, 검색·목록, 문형 묶음, 정적 검사 2종.

**버린다** — 화면 전체(`tpl.html`). 헤더부터 버튼까지 치수가 다 다르므로 고쳐 쓰기보다 한자 앱 구조 위에 다시 얹는 편이 빠르고 일관된다.
